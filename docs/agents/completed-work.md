- ✅ Admin shade review queue (#45) — `/api/shades-admin/review*` (`admin-shade-review.ts`, `src/lib/shade-review.ts`; migration `20261017063252270_shade-review-queue`): lists `user_submitted` shades with submitter counts and `pg_trgm` merge candidates; approve (→ `active`, optional edits), merge into an active shade (one transaction; inventory re-pointed, a user's duplicate rows combined generically from `pg_attribute` so new inventory columns are carried; vendor listings (`shade_source_product`) and learned barcodes move to the target; source retired in place with `review_status = 'merged'` + `merged_into_shade_id`, still private and hidden from user polish queries), or reject (stays private). Who/when/what is recorded on the shade (`reviewed_by_user_id`, `reviewed_at`, `review_status`, `review_note`)
- ✅ Capture API — barcode/label/color frame submission with adaptive question flow (`capture.ts`); barcode scans match the catalog end to end (#21, #325: ingestion + backfill write `barcode` rows, connector-GTIN fallback, decoded barcode frames answer in one round trip, unknown barcodes are learned per user); read-only `POST /api/capture/{captureId}/check` returns the match plus the caller's relationship (owned/wishlisted/notOwned) without touching inventory, via `classifyInventoryOwnership` in `src/lib/inventory-relationship.ts` (from the inventory `status` column: only `owned` rows count as owned)
- ✅ Catalog search — `pg_trgm`-based fuzzy search across brand/shade names and aliases (`catalog.ts`)
- ✅ Image proxy — private blob storage served through `/api/images/{id}` (`images.ts`); ids are HMAC-signed, expiring capabilities. Public `v2` ids (anonymous, `Cache-Control: public`) read only the source-image container; owner-scoped `v3` ids for private media (#227) read only `USER_MEDIA_CONTAINER` and are served only to the owner's bearer token (401/403 otherwise, `Cache-Control: private` + `Vary: Authorization`)
- ✅ Per-user access control (#47) — all user-data routes use `withAuth` with `user_id`-scoped SQL; admin/ops routes use `withAdmin`; capture frames can only reference the caller's own `image_asset` rows; user-created shades are `user_submitted` (private until an admin approves them in the review queue; rejected and merged submissions stay private, merged ones are hidden even from their creator), shared shades are read-only for users (catalog finishes/colors are written only when the request creates the shade, #224), and email account-linking requires a verified email
