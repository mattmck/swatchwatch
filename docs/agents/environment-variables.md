# Environment Variables

Covers every environment variable by group (Functions, eval/admin scripts, web, mobile, infra) and where each set lives.

Where each set lives: Functions → `packages/functions/local.settings.json` (copy `local.settings.json.example`, which lists every setting in the groups below; Terraform-managed app settings + Key Vault references in Azure). Web → build-time `NEXT_PUBLIC_*` (`apps/web/.env.local` locally, since Next.js reads env files from `apps/web` only; `.github/workflows/deploy.yml` in CI). Mobile → `apps/mobile/.env.local` (from `.env.example`). Migrations → `npm run migrate` / `migrate:down` copy every `local.settings.json` value into the environment first (overriding exported or inline variables of the same name, `PG*` included), then use `DATABASE_URL` if set, else `PG*`; to target another database export `DATABASE_URL` (the example defines none). Infra → GitHub environment variables/secrets read by `deploy-infra.yml`. Full tables with defaults: `packages/functions/README.md` → Environment Variables, `apps/web/README.md`, `apps/mobile/README.md`, `infrastructure/README.md`. The `NEXT_PUBLIC_*` entries in `local.settings.json.example` are a convenience copy; the Functions host ignores them. When adding a variable, put it in the matching group here, in the Functions README table and in `local.settings.json.example`. Flags are on only for the exact value `true`.

## Functions: runtime, database, auth

- `FUNCTIONS_WORKER_RUNTIME` (`node`), `AzureWebJobsStorage` (host storage; Azurite locally). `FUNCTIONS_NODE_BLOCK_ON_ENTRY_POINT_ERROR=true` (Terraform-managed) makes import failures fail startup instead of route 404s. `WEBSITE_HOSTNAME` / `WEBSITE_INSTANCE_ID` are set by Azure, never by us: `src/lib/runtime-env.ts` uses them to detect a hosted instance.
- `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` — Postgres (local `localhost:55432`). Pool: `PG_POOL_MAX` (10), `PG_IDLE_TIMEOUT_MS` (30000), `PG_CONNECTION_TIMEOUT_MS` (15000), `PG_QUERY_MAX_RETRIES` (2, retry-safe `SELECT` / `UPDATE ingestion_job` on connection timeouts), `PG_QUERY_RETRY_BASE_MS` (250). `DATABASE_URL` is read only by `npm run migrate` and `migrate:down`, ahead of `PG*` (an exported value works because `local.settings.json` normally has none); the DB scripts (`eval:hex:populate`, `backfill:product-text`) read `PG*`.
- `AZURE_AD_B2C_TENANT`, `AZURE_AD_B2C_CLIENT_ID` — token validation (`src/lib/auth.ts`).
- `AUTH_DEV_BYPASS` — enables `Bearer dev:<userId>` tokens for local dev only. Fails closed when hosted in Azure (`WEBSITE_INSTANCE_ID` or a non-loopback `WEBSITE_HOSTNAME`); the deploy workflow always sets it to `false`.

## Functions: storage, image proxy, private media

- `AZURE_STORAGE_CONNECTION` — storage account (Azurite locally). Unset: ingestion keeps source image URLs, the orphan sweep is skipped.
- `BLOB_STORAGE_MAX_CONNECTIONS` — sockets per storage origin in the pooled keep-alive undici Agent all Blob Storage REST calls use (default `16`, clamped 1–128; `src/lib/storage-http.ts`); bounds outbound SNAT use on the Consumption plan. Blob PUT and existence checks retry connect errors and 429/5xx; existence checks are Get Blob Metadata (`GET ?comp=metadata`), never HEAD, because undici closes the socket after every HEAD (one new connect and SNAT port per check, which starved the image proxy during the thumbnail backfill); vendor downloads keep the default dispatcher. Terraform-managed (`blob_storage_max_connections`, from the `BLOB_STORAGE_MAX_CONNECTIONS` GitHub environment variable in Deploy Infra, default `16`).
- `SOURCE_IMAGE_CONTAINER` (`source-images`, catalog images + variants; the only container `v2` ids read), `USER_MEDIA_CONTAINER` (`nail-photos`, private user media; the only container `v3` ids read, #227), `CONNECTOR_RAW_CONTAINER` (raw connector snapshots + ingestion catalog cache + sitemap crawl checkpoints; unset = no-op, and a `SitemapJsonLd` source cannot run; legacy name `RAW_SNAPSHOT_CONTAINER` still read but deprecated).
- `IMAGE_PROXY_SIGNING_KEY` — secret (>= 32 chars) that HMAC-signs `/api/images/{id}` capability ids (`src/lib/image-proxy.ts`) and roots shareable wishlist and look tokens. Fails closed when unset (image URLs omitted, proxy refuses requests) unless dev bypass is active, which uses an ephemeral per-process dev key. Terraform generates it into Key Vault (`image-proxy-signing-key`).
- `IMAGE_PROXY_ID_TTL_SECONDS` — minimum lifetime of public `v2` ids (default `259200` = 3 days, clamped 1h–30d; keep above the AI batch completion window plus poller lag, since the poller re-reads the same ids for the snap step and an expired id just keeps the raw `vision-direct` hex).
- `IMAGE_PROXY_PRIVATE_ID_TTL_SECONDS` — minimum lifetime of owner-scoped `v3` ids (default `3600`, clamped 300–86400, bucketed to 15 minutes).
- `IMAGE_PROXY_LEGACY_ID_ACCEPT_UNTIL` — optional ISO-8601 cutoff for accepting legacy non-expiring `v1` ids (unset = rejected).
- Orphan media sweep (#319, `src/lib/orphan-media-sweep.ts`): `ORPHAN_MEDIA_SWEEP_SCHEDULE` (NCRONTAB, default `0 17 3 * * *`), `ORPHAN_MEDIA_SWEEP_GRACE_SECONDS` (minimum `captured_at` age, default `86400`, clamped 3600–2592000), `ORPHAN_MEDIA_SWEEP_BATCH_SIZE` (per scan query, default `100`, clamped 1–1000), `ORPHAN_MEDIA_SWEEP_MAX_PER_RUN` (default `2000`, clamped 1–20000; the rest wait for the next run).
- Capture frames (Bottle Flow slice A, `src/lib/capture-frame-sweep.ts`): `CAPTURE_FRAME_SWEEP_SCHEDULE` (NCRONTAB, default hourly `0 0 * * * *`), `CAPTURE_FRAME_RETENTION_SECONDS` (age by `image_asset.captured_at` before the sweep releases a frame blob, default `86400`, clamped 3600–604800), `CAPTURE_FRAME_SWEEP_BATCH_SIZE` (per scan query, default `200`, clamped 1–1000), `CAPTURE_FRAME_SWEEP_MAX_PER_RUN` (default `2000`, clamped 1–20000). The sweep runs whether or not `BOTTLE_CAPTURE_ENABLED` is on; blobs are only written while it is on and `AZURE_STORAGE_CONNECTION` is set.

## Functions: feature flags

Every flag below is read through `isFeatureEnabled()` in `src/lib/feature-flags.ts` (#313, D22): one registry mapping flag name → env var and public/internal, fail closed (only `true`, trimmed, any case; `HEX_DETECTION_BATCH_ENABLED` also keeps its older `1`/`yes`/`on`). Public flags (the two share flags and `bottleCapture`) are reported by anonymous `GET /api/config/flags` (`{ flags: { shareableWishlist, shareableLooks, bottleCapture } }`, cached 60 s) and the web reads them once through `useFeatureFlags()` (`apps/web/src/lib/use-feature-flags.ts`); the hex flags are never exposed. Adding a flag = one registry entry (plus `FEATURE_FLAG_NAMES` in `packages/shared` if clients need it). A move to Azure App Configuration (when per-user targeting is needed) changes `isFeatureEnabled` only.

- `SHAREABLE_WISHLIST_ENABLED` (#268, default `false`) — off → every wishlist-share route returns 404 `feature_disabled` and the web share card is hidden. Needs `IMAGE_PROXY_SIGNING_KEY`. Terraform-managed (`shareable_wishlist_enabled`, from the `SHAREABLE_WISHLIST_ENABLED` GitHub variable in Deploy Infra).
- `SHAREABLE_LOOKS_ENABLED` (default `false`) — off → `/api/look-share` and `/api/look/{token}` return 404 `feature_disabled` and the Looks page shows no Share link controls. Needs `IMAGE_PROXY_SIGNING_KEY`. Terraform-managed (`shareable_looks_enabled`, from the `SHAREABLE_LOOKS_ENABLED` GitHub variable in Deploy Infra).
- `BOTTLE_CAPTURE_ENABLED` (default `false`) — guided bottle recognition on the capture API: brand hint at session start, `nextFrame` photo prompts, unmatched-bottle prefill. While off, the capture API's responses are unchanged. Terraform-managed (`bottle_capture_enabled`, from the `BOTTLE_CAPTURE_ENABLED` GitHub variable in Deploy Infra); reported to clients as `bottleCapture` by `GET /api/config/flags`.
- `HEX_DETECTION_BATCH_ENABLED` (default `false`) — batch mode for Shopify vision hex detection and the `ingestion-ai-batch-poller` timer.
- `HEX_DETECTION_SNAP_ENABLED` (default `false`) — the snap step (see Shade hexes above); read at call time. Terraform-managed (`hex_detection_snap_enabled`, from the `HEX_DETECTION_SNAP_ENABLED` GitHub variable).

## Functions: Azure OpenAI and hex detection

- Client (`src/lib/azure-openai-config.ts`): `AZURE_OPENAI_ENDPOINT` + `AZURE_OPENAI_KEY` (`api-key` header); always the Azure OpenAI resource directly (APIM gateway removed, D25).
- Deployments: `AZURE_OPENAI_DEPLOYMENT` (fallback for all), `AZURE_OPENAI_DEPLOYMENT_HEX` (sync vision detection), `AZURE_OPENAI_DEPLOYMENT_HEX_BATCH` (batch; → `_HEX` → `AZURE_OPENAI_DEPLOYMENT`), `AZURE_OPENAI_DEPLOYMENT_LABEL` (label OCR extraction and the bottle sticker read in `lib/sticker-read.ts`, `STICKER_READ_DEPLOYMENT_ENV_KEYS`; → `_HEX` → `AZURE_OPENAI_DEPLOYMENT`); the bottle glass-color pick (`lib/glass-color.ts`) uses `_HEX` → `AZURE_OPENAI_DEPLOYMENT`. Prompt versions: `GLASS_PROMPT_VERSION` = `glass-palette-pick/2026-11-v2`, `STICKER_READ_PROMPT_VERSION` = `sticker-read/2026-11-v4` (bump when the prompt changes, like `PROMPT_VERSION`).
- `AZURE_OPENAI_VISION_DETAIL` — `low` (default, flat ~85 tokens/image), `high` or `auto`, sync and batch.
- Reasoning models (`src/lib/azure-openai-request.ts`): a deployment whose name starts with `gpt-5`, `o1`, `o3` or `o4` (any case), or is listed in `AZURE_OPENAI_REASONING_DEPLOYMENTS` (comma list, for names that hide the model; `alias=model`, e.g. `vision-prod=o3-mini`, applies that model's effort rules to the alias, a bare alias is treated like gpt-5; a `!name` entry forces a prefix-matching deployment to non-reasoning), gets `max_completion_tokens` (the call's `max_tokens` × 4, at least 1024: reasoning tokens count against it), `reasoning_effort` from `AZURE_OPENAI_REASONING_EFFORT` (`minimal` default, `low`, `medium`, `high`; `minimal` is sent as `low` to o-series and gpt-5.1+ deployments and none is sent to `o1-preview` / `o1-mini`), the chat `api-version` `2025-04-01-preview` on direct chat-completions calls (`REASONING_CHAT_API_VERSION`; older versions reject those fields; batch JSONL lines carry none, the upload and batch creation use `AZURE_OPENAI_BATCH_API_VERSION`) and no `temperature` (a non-zero one, such as the eval `ensemble`'s, is dropped with a one-time warning). Request builders keep writing gpt-4o fields; `applyChatCompletionModelParams` rewrites them once the deployment is known (sync executor, batch JSONL lines, label OCR, color-name detection), so gpt-4o / gpt-4.1 requests are unchanged and no prompt version moves.
- Sync pacing: `HEX_DETECTION_CONCURRENCY` (default `4`, max `32`; DB writes stay sequential; capped by the deployment's TPM quota, so raise together with capacity), `HEX_DETECTION_DELAY_MS` (pause after each call per slot, default `1000`, max `60000`, `0` disables; 429s are still retried with `Retry-After`).
- **Functions: AI record/replay** (`src/lib/ai-replay.ts`; local test harness only, deliberately not Terraform-managed, like the eval/admin-script settings): the capture AI calls (Azure OpenAI chat completions via `ai-color-detection.ts` (sticker read, glass pick, hex detection, palette pick), the label parse in `ocr-parser.ts`, Document Intelligence in `ocr.ts`) use `aiReplayFetch` instead of `fetch`; the batch pipeline and image downloads do not. `AI_REPLAY_MODE` (`off` default; `record` = real call, response stored (overwrites); `replay` = fixtures only, a miss throws `AiReplayMissError` with the key and request summary, never a network fallback, never retried); forced `off` on a hosted Azure instance (`isHostedInAzure`, logged once), like `AUTH_DEV_BYPASS`. `AI_REPLAY_DIR` (store root, default `packages/functions/eval/ai-replay`, one committed `<service>/<sha256>.json` per request: key over method, path without host, query without credential params, sorted JSON body with image payloads replaced by `sha256:<bytes hash>`; fixtures never hold image bytes or `api-key` / `Ocp-Apim-Subscription-Key` / `Authorization`). `AI_REPLAY_RECORD_MISSING_ONLY` (`true`: record only misses). A local host in record/replay mode adds `aiReplayMode` to `GET /api/config/flags` (never in Azure), which `eval:bottle` prints and `tests/capture-replay.e2e.test.cjs` requires (CI starts no host, so it runs locally only; see `packages/functions/README.md` → AI record/replay).
- `HEX_SNAP_MAX_DISTANCE` — largest OKLAB distance at which the snap step (production and the eval `blind-snap` / `image-select-ai-snap` strategies) replaces the model's hex with the nearest measured palette chip (default `0.10`, the MEDIUM threshold).
- Suspicious vendor hexes (`src/lib/suspicious-hex.ts`, used when `detectHexOnSuspiciousOnly` is on): `SUSPICIOUS_HEX_REPEAT_MIN_RECORDS` (default `3`) and `SUSPICIOUS_HEX_REPEAT_MIN_SHARE` (0–1, default `0.1`) — a vendor hex repeated at least that often in one source's batch is a store template default (both must be met); `SUSPICIOUS_HEX_GRAYSCALE_MAX_CHROMA` (default `0.02`) — near-grayscale vendor hexes are flagged unless the name/tags suggest gray/silver/black/white/nude/chrome.
- Batch pipeline: `HEX_DETECTION_BATCH_MIN_IMAGES` (records before switching to batch, default `5`), `HEX_DETECTION_BATCH_MAX_IN_FLIGHT` (pending batches per job before pausing for `awaiting_ai`, default `20`, clamped 1–100), `AZURE_OPENAI_BATCH_API_VERSION` (default `2025-03-01-preview`), `AZURE_OPENAI_BATCH_COMPLETION_WINDOW` (default `24h`), `INGESTION_AI_BATCH_POLL_SCHEDULE` (NCRONTAB, default `0 * * * * *`), `INGESTION_AI_BATCH_MAX_POLL_JOBS` (default `10`), `INGESTION_AI_IMAGE_PROXY_ORIGIN` (public origin for the `/api/images/{id}` URLs sent to Azure OpenAI; defaults to `https://$WEBSITE_HOSTNAME`).

## Functions: ingestion and catalog images

- `INGESTION_JOB_QUEUE_NAME` (default `ingestion-jobs`).
- `INGESTION_WORKER_TIME_BUDGET_MS` — wall-clock budget per worker invocation (default `240000`, clamped 30000–270000); when spent, the worker saves `metrics.checkpoint`, sets stage `continuation_queued` and enqueues a continuation so long jobs survive the Consumption plan timeout. A message that fails all 5 deliveries (`host.json` `maxDequeueCount`) lands in `${INGESTION_JOB_QUEUE_NAME}-poison`, where the `ingestion-job-poison` trigger marks its job `failed` (stage `queue_poisoned`, so `ingestion.job_failed` fires) unless it is a stale duplicate (`resolveIngestionResumePoint` drop) or the job is in `awaiting_ai` (`planPoisonedIngestionMessage`).
- `INGESTION_LOG_FLUSH_INTERVAL_MS` (default `10000`); `INGESTION_JOB_LOG_MAX_ENTRIES` (entries kept in `metrics_json.logs` across all invocations and poller runs, default `500`, clamped 100–2000; first 20% kept, then the newest, with one marker counting the omitted lines by level, `src/lib/job-log.ts`).
- Shopify: `SHOPIFY_CONNECTOR_REQUEST_TIMEOUT_MS` (default `45000`), `SHOPIFY_CONNECTOR_MAX_RETRIES` (default `2`), `SHOPIFY_CONNECTOR_RETRY_BASE_DELAY_MS` (linear backoff base, default `1000`), `SHOPIFY_CONNECTOR_PAGE_DELAY_MS` (pause between consecutive page requests to one store, default `1000`, clamped 0–10000), `SHOPIFY_CONNECTOR_MAX_PAGES` (pages of 250 products read per run, default `30`, clamped 1–200; a source overrides it with `data_source.metadata.maxPages`, e.g. Beyond Polish's 71 pages).
- Sitemap + JSON-LD crawl (`lib/connectors/sitemap-jsonld.ts`): `SITEMAP_JSONLD_MAX_PAGES_PER_RUN` (product pages fetched per pull while the crawl is incomplete, default `150`, clamped 10–300), `SITEMAP_JSONLD_SAVE_MARGIN_MS` (time kept before the worker deadline to save the crawl checkpoint and hand off, default `20000`, clamped 5000–120000). Requests are 1 s apart (`SHOPIFY_CONNECTOR_PAGE_DELAY_MS`, at least 1000 here) and reuse the Shopify timeout/retry settings; the crawl needs `CONNECTOR_RAW_CONTAINER` (a durable catalog cache). Terraform-managed (`sitemap_jsonld_max_pages_per_run`, `sitemap_jsonld_save_margin_ms`).
- `PRODUCT_FEED_AUTH_<SOURCE>` — optional HTTP basic auth (`user:pass`) for one Google product feed source, read only when its `data_source.metadata.feedAuthEnv` names the variable, which must match `^PRODUCT_FEED_AUTH_[A-Z0-9_]+$` (any other name fails the job before a request); never logged. Terraform owns the Function App's app settings, so a value set only by hand is removed by the next apply: add it to `main.tf` as a Key Vault reference (or to `ignore_changes`) as `infrastructure/README.md` describes. A per-source secret set by hand as an app setting / Key Vault reference (no Terraform variable). Feed requests reuse the `SHOPIFY_CONNECTOR_REQUEST_TIMEOUT_MS` / `_MAX_RETRIES` / `_RETRY_BASE_DELAY_MS` settings.
- `SOURCE_IMAGE_MAX_EDGE_PX` — long edge above which catalog images are downscaled before storage (default `2048`, clamped 256–8192); images still over 5 MB after resizing are re-encoded as WebP. `SOURCE_IMAGE_MAX_DOWNLOAD_BYTES` — largest download accepted before resizing (default 25 MB, clamped 5–100 MB).
- `SOURCE_IMAGE_MAX_PER_PRODUCT` — max images (primary included) ingestion downloads and stores per product per run (default `8`, clamped 1–50; unset/empty/`0`/invalid = 8, no unlimited value). Keeps the primary, the image AI detection would choose (even past the cap), then vendor order; an already-stored image past the cap is reused; the rest are skipped (`imagesSkippedByCap`; `src/lib/product-image-cap.ts`).
- `GALLERY_MAX_IMAGES_PER_SHADE` — max `source_gallery` images one product links per ingest, after near-duplicate skipping, in vendor order (unset/empty/`0`/invalid = unlimited, the default). Images past the cap are still stored; the AI detection image is always linked; lowering it unlinks the extras on the next ingest (`src/lib/gallery-dedupe.ts`).

## Functions: OCR, voice, cache, HTTP, telemetry

- `AZURE_DOCUMENT_INTELLIGENCE_ENDPOINT`, `AZURE_DOCUMENT_INTELLIGENCE_KEY` — label OCR (`src/lib/ocr.ts`); skipped when either is missing.
- `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` — reserved for the voice stub; not read yet.
- `REDIS_URL`, `REDIS_KEY` — read-through cache (`src/lib/cache.ts`); either missing → no-ops, Postgres only.
- CORS (`src/lib/http.ts`): `CORS_ALLOWED_ORIGINS` (comma-separated, default `http://localhost:3000,https://*.azurestaticapps.net`; Terraform sets the web origins), `CORS_ALLOWED_METHODS` (default `GET,POST,PUT,PATCH,DELETE,OPTIONS`), `CORS_ALLOWED_HEADERS` (default `Content-Type, Authorization, traceparent, tracestate, Request-Id, Request-Context`, so browser telemetry can correlate), `CORS_SUPPORT_CREDENTIALS` (`true` adds `Access-Control-Allow-Credentials` for matched origins; default off). `withCors` is the only CORS layer everywhere: the Function App has no platform CORS (`site_config.cors`, which would answer preflights itself and drop the app's headers) and `local.settings.json.example` has no `Host.CORS`, so every HTTP route must list `"OPTIONS"` in `methods` and wrap its handler in `withCors` (the host 404s an unlisted OPTIONS; `tests/http-routes.unit.test.cjs` checks both). For a web dev server on another port add its origin to `CORS_ALLOWED_ORIGINS`.
- `APPLICATIONINSIGHTS_CONNECTION_STRING` — telemetry sink for `trackEvent`/`trackMetric`/`trackException`; `src/index.ts` imports `lib/telemetry` first so dependencies are auto-instrumented and correlated with the host request (keep it first).

## Hex eval and admin scripts (never read by the Function App)

- Admin scripts (`backfill:*`, `dedupe:gallery-images`, `dedupe:makeupapi-shades`, `remove:source-images`, `eval:bottle`): `API_BASE_URL` (default `http://localhost:7071/api`), `ADMIN_BEARER_TOKEN` (an admin token, or `dev:<adminId>` locally). `eval:bottle` additionally reads `PG*` and `AZURE_STORAGE_CONNECTION` / `USER_MEDIA_CONTAINER`, filled from `local.settings.json` when unset.

## Infra (GitHub environment settings read by `.github/workflows/deploy-infra.yml`, exported as `TF_VAR_*`; see `infrastructure/README.md`)

- `ALERT_EMAIL` — address the prod alert action group emails (`TF_VAR_alert_email`). Set it as an environment **secret** so it is masked in logs (a variable also works); never commit it to tfvars.
- `ALERTS_ENABLED` — optional override for `TF_VAR_alerts_enabled` (default `true` for `prod`, `false` otherwise).
- `SHAREABLE_WISHLIST_ENABLED`, `SHAREABLE_LOOKS_ENABLED`, `BOTTLE_CAPTURE_ENABLED`, `HEX_DETECTION_BATCH_ENABLED`, `HEX_DETECTION_SNAP_ENABLED` — feature flags exported to the matching Terraform variables (default `false`).
- `ENABLE_DOCUMENT_INTELLIGENCE` — `true` provisions the Document Intelligence account (`TF_VAR_enable_document_intelligence`, default `false`), which sets the Function App's `AZURE_DOCUMENT_INTELLIGENCE_*` settings and turns on label OCR; without it label frames are stored but never read.
- `BLOB_STORAGE_MAX_CONNECTIONS` — exported as `TF_VAR_blob_storage_max_connections` (default `16`), set on the Function App by Terraform.
- Function App runtime settings — every other app setting the Functions code reads (pool sizes, timeouts, schedules, TTLs, CORS lists, hex-detection pacing, the four `CAPTURE_FRAME_*` capture-frame sweep settings) has a GitHub environment variable of the same name, exported as `TF_VAR_<lowercase name>` with the code default as fallback (full list in `infrastructure/README.md`). Only eval/admin-script settings, the local-only `AI_REPLAY_*` test-harness settings (forced off in Azure), the `NEXT_PUBLIC_*` convenience copies and Azure's own `AzureWebJobsStorage` / `APPLICATIONINSIGHTS_CONNECTION_STRING` / `WEBSITE_*` stay out. A new Functions setting gets a Terraform variable, a `main.tf` app setting, a `deploy-infra.yml` line and a GitHub variable in `dev` and `prod`.
- Also required per environment: secrets `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID`, `AZURE_AD_B2C_CLIENT_ID`; variables `TFSTATE_*`, `AZURE_AD_B2C_TENANT`, `AUTH_DEV_BYPASS` (Terraform only; the app deploy forces `false`), `CREATE_OPENAI_RESOURCES`, `OPENAI_DEPLOYMENT_NAME` and the `OPENAI_BATCH_*` deployment settings (list in `infrastructure/README.md`).
- `MANAGE_CIAM_SERVICE_PRINCIPAL` — `true` lets Terraform import and manage the web sign-in app's service principal in the External ID tenant (`app_role_assignment_required = false`); default `false`. Needs `CIAM_TENANT_ID` and `CIAM_TERRAFORM_CLIENT_ID` (deployer app in the CIAM tenant with a GitHub OIDC federated credential + Cloud Application Administrator; one-time bootstrap in `infrastructure/README.md`).
- `OPENAI_LOCATION` / `OPENAI_REGIONS` — the environment's Azure OpenAI region (prod: `centralus`; dev: `eastus`; `OPENAI_REGIONS` JSON list takes precedence), exported as `TF_VAR_openai_location` / `TF_VAR_openai_regions`. Required when `CREATE_OPENAI_RESOURCES` is true: the workflow has no default region (an OpenAI account's region is immutable, so a different region replaces and soft-deletes the account; 2026-10-19 prod incident). Manual `Deploy Infrastructure` dispatches leave the `openai_location` input empty, and a plan that deletes or replaces any `azurerm_cognitive_account` / `azurerm_cognitive_deployment` is refused between plan and apply unless the `allow_openai_replace` input is true (see `infrastructure/README.md` → Azure OpenAI region and replacement guard)
