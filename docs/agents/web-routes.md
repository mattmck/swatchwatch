# Web App Routes

Covers every route of the Next.js web app (`apps/web`) with its file and behaviour, plus the route groups. CLAUDE.md keeps a compact route → file table.

The web app uses Next.js route groups to separate public marketing pages from the authenticated app:

| Route | File | Notes |
|-------|------|-------|
| `/` | `src/app/(marketing)/page.tsx` | Landing page — hero, features, color showcase, CTA |
| `/dashboard` | `src/app/(app)/dashboard/page.tsx` | Client component, getting-started checklist while the user owns < 5 polishes (`GettingStarted`: import / scan / catalog search + a 20-swatch progress strip, per-user localStorage dismissal, `onboarding.step_clicked`; the rules live in `packages/shared/src/onboarding.ts`, `lib/onboarding.ts` adds the web routes; a brand-new user sees only it and one stats empty state) + stats + "Pick for me" card + recent additions + collection stats panels (spend by brand/month per currency, worn vs waiting + untried %, most-worn, cost per wear) via `GET /api/stats/collection`; the Wishlist tile's count and subtitle (brand list-price total per currency, unpriced polishes counted) come from the same stats response's `wishlist` |
| `/admin` | `src/app/(admin)/admin/page.tsx` | Unified admin console — tabs: Configuration, Job Runs, Admin Jobs, Sources, User Management, Review Queue, Hex Labeling, Bottle Eval, Backfills; active tab synced to `?tab=` (`?tab=review-queue`; `?tab=sources`: the Sources tab after Admin Jobs, with a Sites / Brands switch: Sites lists every `data_source` with its store permission and turns it on, off or runs it, Brands lists every `brand` (zero-shade ones too) with its own store, retailers and ingest profile, state in the URL (`view`, `kind`, `enabled`, `permission`, `supply`, `q`, `sort`, `dir`, `open`); `?tab=hex-labeling`: eyedropper ground-truth hex labeler for the hex-detection eval; `?tab=bottle-eval`: label a bottle and photograph its front/bottom/glass/box as a private eval sample); the Review Queue tab also holds the Product categories panel (backfill dry run/apply, held accessories, sticky Category control, #349); `?tab=backfills` runs the `npm run backfill:*` jobs (thumbnails, barcodes, gallery dedupe, product text, empty finishes, product prices, imported wishlist rows, MakeupAPI duplicates, products a brand store no longer accepts) from the browser, one keyset batch per request with dry run / apply, stop and resume (`backfills-tab.tsx`; product text/finishes/price via `functions/product-data-admin.ts`) |
| `/admin/reference-data` | `src/app/(admin)/admin/reference-data/page.tsx` | Legacy redirect → `/admin?tab=configuration` |
| `/admin/jobs` | `src/app/(app)/admin/jobs/page.tsx` | Legacy redirect → `/admin?tab=admin-jobs` |
| `/polishes` | `src/app/(app)/polishes/page.tsx` | Client component, filterable/sortable table; `Pagination` (Previous / at most 7 page slots / Next on desktop; one-line ‹ Page N of M › jump picker on phones; range and rows-per-page as secondary controls; scrolls to the top on page change; `lib/pagination.ts`); admins get an Admin column with Recalc and a one-tap "Accessory" category action (`MarkAccessoryButton`); status chips + untried badge, optimistic row quick actions (♡ wishlist, ✓ own, status/tried menu), `status=` / `untried=` URL filters, color family chips (`?family=`), Category chips (`?category=`, #349), category pill on non-color rows and a neutral topper swatch; header "Export" menu downloads the collection as CSV/JSON; the first page of the My Collection preset (`status=owned`, per filter set) is saved per user in localStorage (`lib/api-cache.ts`, 7 days, no private `v3` URLs) and shown under a "Showing your saved collection" banner with writes and export disabled when the API is unreachable; empty views show `PolishesEmptyState` (empty My Collection: Browse the catalog + Import); `?focus=search` focuses the search box; the page opens offline from the service worker's precached app shell; the Wishlist view shows a value line (count, brand list-price total per currency with priced counts, polishes without a price, "as of" hint; `WishlistValue`) |
| `/polishes/new` | `src/app/(app)/polishes/new/page.tsx` | Client component, form with color picker + star rating; accepts `?barcode=` / `barcodeFormat` (and prefilled brand/name) from Rapid Add's Add manually link and sends the barcode with the create request (#21); in edit mode an emptied rating is sent as `null` so it is cleared (#441) |
| `/polishes/detail` | `src/app/(app)/polishes/detail/page.tsx` | Client component, detail shell driven by query params; admins get a "Catalog data" card (`AdminCatalogSection`: sticky category select + Mark as accessory, and the vendor listings behind the shade with their raw / normalized JSON from `GET /api/shades-admin/{id}/source-products`); owned polishes show a read-only "Worn N times" wear-history panel (`WearHistoryPanel`, newest 5 manis via `GET /api/manicures?shadeId=`, "Show all" → `/manis?shade=<id>`); admins also get a collapsed "Sip ground-truth hex" panel (`AdminHexSipPanel`, #351); owned polishes show the private nail photo (`NailPhotoPanel`) beside the vendor/AI swatches; a visited owned polish also opens from its saved copy when offline (read-only, nail photo placeholder, telemetry `collection.offline_shown`) |
| `/polishes/looks` | `src/app/(app)/polishes/looks/page.tsx` | Client component, Looks: vibe chips (occasion, mood, finish, Owned only, Include toppers, optional skin tone undertone/depth that softly reorders bases and accents, shared `looks/skin-tone.ts`; `?occasion=&mood=&finish=&owned=1&toppers=0&undertone=&depth=&seed=` URL state) → three looks from owned polishes via the pure, seeded `recommendLooks()` in `apps/web/src/lib/looks.ts` (18 named templates, harmony/finish-aware, diverse bases), gaps filled from the catalog and marked "Add"; per-step Swap, Shuffle, Save (account via `/api/looks`, pending localStorage fallback) + Saved tab, "Wear this" → `ManiLogForm` prefilled with roles, "Add missing items" shopping list (buy links, ♡ wishlist through the add guard, copy text), a Details drawer (application order, finish notes, substitutions), "Copy look" (text + vibe/seed link, no server state), "Share link" (public `/l/` link for a saved look, behind `SHAREABLE_LOOKS_ENABLED`) and a cosmetic skin-tone swatch backdrop, "Color Lab" links (card, drawer, saved look) to `/polishes/search` seeded with the look's colors (`lookColorLabHref`); telemetry `looks.generated` / `looks.wear_clicked` / `looks.color_lab_opened` |
| `/polishes/gaps` | `src/app/(app)/polishes/gaps/page.tsx` | Client component, collection gap heatmap (hue × lightness coverage + next-buy targets) |
| `/polishes/match` | `src/app/(app)/polishes/match/page.tsx` | Client component, photo → polish color matching via `POST /api/polishes/match-image` (#105): upload/drop/camera, drag to focus on an area, scope (collection / wishlist / catalog) + finish + color family filters, palette chips (background/skin hidden by default, tap to drop), per-color or flat results with confidence legend, ♡ wishlist / ✓ Own row actions behind the add guard; filters and palette choices in the URL (`lib/photo-match-url.ts`), photo kept in memory (`lib/photo-match-session.ts`) so Back restores it |
| `/polishes/import` | `src/app/(app)/polishes/import/page.tsx` | Client component, CSV import wizard (upload → column mapping → review matched/ambiguous/unmatched with candidate picker → commit → summary) via `/api/polish-imports` |
| `/polishes/search` | `src/app/(app)/polishes/search/page.tsx` | Client component, canvas color wheel + OKLAB matching over the whole owned color collection plus the catalog rows nearest the current targets (`GET /api/polishes?nearHex=`, throttled latest-wins `LatestLoader` in `lib/color-search-nearby.ts`; the hover color is queried only in Similar mode, and the list is dimmed under "Updating catalog matches…" until the rows for the current colors arrive; 100 rows rendered at a time); all state in the URL (`lib/color-search-url.ts`); a safe `?returnTo=` (e.g. from a look's Color Lab link) shows a "Back to …" link |
| `/manis` | `src/app/(app)/manis/page.tsx` | Client component, mani log: recent-weeks calendar strip + history list, "Log a mani" dialog (polishes with roles, date, notes); `?log=<shadeId>` preselects a polish, `?shade=<shadeId>` filters the calendar and history to manis with that polish (clear chip) |
| `/rapid-add` | `src/app/rapid-add/page.tsx` | Client component, camera-first Rapid Add: live `getUserMedia` rear camera, on-device barcode (`BarcodeDetector`, lazy `@zxing/library` fallback), frames → capture API, "Scanned ✓" pill and green guide-box flash while checking (the result headline stays over the viewfinder), live scanning that keeps running (a repeat read says "Already scanned", a new barcode on a verdict starts the next bottle; `planLiveBarcode`), an auto-shutter for asked-for photos (bottle prompts, the label after an unknown barcode: fires once the bottle has been brought into the guide outline and held steady, sharp and exposed for 1 s, measured on the guide's region only, `lib/auto-shutter.ts`, on/off toggle), a scanned barcode's verdict from the frame response (own it / on your wishlist / add or wishlist, with swatch; nothing added until the user says so; a not-owned shade whose owned HIGH/MEDIUM near-dupes come back from `GET /api/polishes/{id}/dupes` (one call, 2 s cap, never blocking) turns into "New to you — but close" with up to 3 dupe swatch pairs, Add anyway / Wishlist instead / Cancel and the `dupe.warning_*` events with `surface = rapid_add`), unknown barcode → "Photograph the label" (same session, learns the barcode) or "Add manually" (`/polishes/new?barcode=…`), verdict card after finalize (own it / added / add), shelf mode below it (`ShelfList`, `lib/rapid-add-shelf.ts`: every verdict of the session newest first with chip, time and the same quick actions, repeat GTIN scans flagged in place, counts strip, Clear shelf; "Scan next" keeps it; sessionStorage per user, ids/names/hexes/verdicts only, cleared on sign-out), mobile-web install prompt; precached by the service worker so it opens offline; with `BOTTLE_CAPTURE_ENABLED` on it is a check-first guided bottle sequence (batch brand header with sticky hints, per-surface prompts with "Can't see it", each shutter/auto-shutter photo carrying the drawn outline as `quality.guideRegion` in fractions of the uploaded frame (`lib/guide-region.ts`), pick list, one-tap create card; only the server's `nextFrame` (or Find match) ends it: a barcode read mid-sequence is just evidence and a photo with a barcode in view stays the prompted surface's frame, `shouldCheckBarcodeFrame` / `stillFrameTarget` in `lib/rapid-add-flow.ts`; "More options" keeps the chips and finalize path); `layout.tsx` adds `RequireAuth` + `AppShell` |
| `/w/?token=…` | `src/app/w/page.tsx` | Public shared wishlist (#268): no auth/AppShell, `noindex` + `no-referrer` metadata. Static export → token is a query param, not `/w/{token}`. Feature behind `SHAREABLE_WISHLIST_ENABLED` (off by default) |
| `/l/?token=…` | `src/app/l/page.tsx` | Public shared look: no auth/AppShell, `noindex` + `no-referrer` metadata, read-only look (template name, vibe, swatches, catalog polishes or color chips, application order) + "Get SwatchWatch". Static export → token is a query param. Feature behind `SHAREABLE_LOOKS_ENABLED` (off by default) |

**Route groups:**
- `(marketing)` — Public pages with glass header + footer (no sidebar)
- `(app)` — Authenticated app pages wrapped in `AppShell` (sidebar navigation)
- `(admin)` — Admin-only pages with `RequireAuth` + `AppShell` at the page level
