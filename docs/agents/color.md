# Color rules

Covers color families (#103), the server-side color-distance sort, estimated-hex ranking and the shared color utilities (OKLAB, harmonies, gaps, Looks).

## Color families and color-distance sort

**Color families (#103):** `classifyColorFamily` in `packages/shared/src/color/color-family.ts` bins a shade's display hex by OKLCH lightness/chroma/hue into red, pink, coral, orange, yellow, green, teal, blue, purple, nude, brown, grey, black or white; `multichrome` comes from finishes (`multichrome`/chameleon/color-shift; duochrome is binned by hex). Postgres mirrors it in `shade_color_family()` and stores it as the generated column `shade.color_family` (migration 20261017061637910_add-shade-color-family), which `?family=` filters on in `GET /api/polishes` and `GET /api/catalog/search`.

**Color-distance sort:** `GET /api/polishes?nearHex=RRGGBB[,…]` (≤ 24, `lib/near-hex.ts`) ranks any filtered list by OKLAB distance from the display hex to the nearest target (shades with a vendor or detected hex first, then *estimated* shades whose display hex is only the name-guessed `name_hex` (`NEAR_HEX_TIER_SQL`), then no hex; shade id tiebreak) and returns `colorDistance` per row; it ranks on the STORED GENERATED `shade.oklab_l/a/b` (migration 20261023001520034_shade-display-oklab, `hex_to_oklab` of the display hex trimmed like `color_family`), and `tests/near-hex.unit.test.cjs` keeps `hex_to_oklab()` equal to the shared `hexToOklab`. Clients never rank a fetched page by color: web color search, polish detail related shades, Looks gap queries and mobile By color (catalog) ask the API; client-side ranking is only for the fully loaded owned collection. Color search on both clients applies the same rule (`isEstimatedDisplayHex`, `compareColorSearchRank`, `colorSearchConfidence` in `packages/shared/src/color/estimated-hex.ts`): an estimated shade ranks after every measured one, never gets a HIGH/MEDIUM grade or a match %, and shows "Estimated color" instead. `tests/color-family.unit.test.cjs` keeps the SQL threshold constants equal to `COLOR_FAMILY_THRESHOLDS`; changing a bin needs a new migration that redefines the function and rewrites the rows.

## Color utilities

**Color utilities:** `apps/web/src/lib/color-utils.ts` provides Hex↔HSL↔RGB↔OKLAB conversions and perceptual `colorDistance()`. Use OKLAB for any color matching/sorting logic. Pure color rules shared by web and mobile live in `packages/shared/src/color/` (OKLAB, color families, dupes, `harmonies.ts` harmony palettes, `pair-it.ts` "Pair it", `gaps.ts` gap-heatmap cells and next buys); `apps/web/src/lib/color-harmonies.ts` is a re-export shim, so add new harmony logic to shared, not the web; likewise the gap rules (`analyzeCollectionGaps`, `gapCellToSeedHex`) live in shared and `color-utils.ts` re-exports them. The Looks recommender (`recommendLooks`, templates, swap/catalog-query helpers, seeded random) is in `packages/shared/src/looks/` too, with `apps/web/src/lib/looks.ts` a re-export shim; the Expo `/looks` screen uses it. Generate hexes from OKLCH with `clampOklchToSrgb` (`color/gamut.ts`, chroma clamp at fixed L and h), not by letting `oklabToHex` clip channels, which shifts hue (gap-cell seed hexes use it).
