# Mobile app

Covers the Expo / React Native app in `apps/mobile` (#109): auth, Rapid Add, Collection, Looks, photos, offline caches and parity rules with the web. See also `apps/mobile/README.md`.

## Mobile app

**Mobile app (#109):** `apps/mobile` is an Expo Router app whose route groups mirror the web (`src/app/(app)/(tabs)` = Collection / Search / Add / Profile behind `Stack.Protected`, `sign-in` outside), with the web's three auth modes (dev bypass `Bearer dev:<id>`, Entra External ID via `expo-auth-session` authorization code + PKCE with tokens in `expo-secure-store`, not configured), every session checked with `POST /api/auth/validate`, and a typed client mirroring `apps/web/src/lib/api.ts` (`src/api/client.ts`). Native Rapid Add (Add tab) scans GTINs on device with `expo-camera` (validated by the shared `barcode/gtin.ts`; iOS's 0-prefixed EAN-13 is sent as the printed UPC-A because `barcode.gtin` lookups are exact), uploads tagged frames with retry, and answers from the read-only `POST /api/capture/{id}/check` (own it / on wishlist / near-dupe / new / pick / not found); it never adds until the user taps Add and keeps a per-user shelf of every verdict across scans (`src/lib/shelf.ts`, cached in AsyncStorage, wiped on sign-out) (`PUT /api/polishes/{shadeId}`, or `finalize` for a shade-less SKU). With `BOTTLE_CAPTURE_ENABLED` (read from `GET /api/config/flags`) the Add tab runs the guided bottle sequence (`components/bottle-prompt.tsx`: server `nextFrame` prompts with Can't see it, auto-check, a per-user remembered brand for batch mode in `src/lib/sticky-hints.ts`) and shows an editable create card that adds an unmatched bottle with `POST /api/polishes` only on a tap. A bottle not in the catalog goes to the manual add form `/polishes/new` (also from Search's empty result), which sends the scanned `barcode` with `POST /api/polishes` so the API learns it privately (`user_shade_barcode`) and runs the add guard on device (`src/lib/manual-add.ts`). Colors come from `packages/shared/src/constants/design-tokens.ts`, generated from the web's `globals.css` by `npm run sync:design-tokens` (CI `--check`). The root `package.json` `overrides` pins `react`/`react-dom` to one version (React Native's renderer must match React exactly). The `/looks` screen (Home panel button) runs the shared Looks recommender with catalog gap fills from `GET /api/polishes?nearHex=` and saves via `/api/looks`, with per-step Swap, a Details sheet, the "Add missing items" shopping list (brand links and list prices, ♡ through the add guard, per-currency subtotals via `sumListPrices`, copy) and Copy look on the web's shared text helpers (`looks/detail.ts`). The Collection tab filters like the web `/polishes` (family and Category chips, Untried, sort; deep-link params `family`/`category`/`untried`/`status`/`sort` as in `polish-list-url.ts`, `src/lib/collection-filters.ts`) and starts with a Home panel (counts, "Pick for me" mirroring `apps/web/src/lib/pick-for-me.ts` in `apps/mobile/src/lib/pick-for-me.ts`, one-tap mani log) and the Manis tab is the mani log; `/gaps` (Home → "Collection gaps") is the hue × lightness heatmap of owned color polishes with next buys, on the shared `color/gaps.ts` rules; the first pages of the Collection, Home counts and mani log are cached per user in AsyncStorage (stale-while-revalidate, wiped on sign-out) and the signed-in user is stored so an offline launch opens the saved data. `/match` matches a camera or library photo with the web's #373 rules (`src/lib/photo-match.ts`), and owned polishes get the private nail photo on the detail screen while the mani log takes optional photos (#396). Private media stays in memory only: owner-scoped `v3` URLs are fetched with the bearer token from the API origin only, held as an in-memory data URI (small LRU, `expo-image` `cachePolicy="none"`, cleared on sign-out), never written to a disk cache or AsyncStorage, and never logged (`src/lib/private-image*.ts`). CI's Mobile job also runs `expo export` for iOS and Android. The polish detail "Edit details" sheet (`components/edit-details-sheet.tsx`, `lib/polish-edit.ts`) edits rating, notes, bottles, price, currency and purchase date (a saved rating or purchase date is cleared with an explicit `null`, a missing key means unchanged), and brand, name, finishes and color only when the polish response says `ownSubmitted` (the caller's own private `user_submitted` shade, #224); for every other shade those stay read-only. A web edit that empties the rating also sends `rating: null`. See `apps/mobile/README.md`. The Home panel opens `/insights` (the web dashboard's collection stats from `GET /api/stats/collection`, per currency, cached like the Home counts), and the Home panel shows the same getting-started checklist below 5 owned polishes (shared `onboarding.ts`, per-user AsyncStorage state, `EmptyState` on Collection / Manis / Looks / Gaps / Insights), and Profile and the Insights header export the collection (`GET /api/polishes/export`) as CSV / JSON through the OS share sheet (`expo-file-system` + `expo-sharing`, temp file in a cache folder cleared before each export and on sign-out), and Profile → Import runs the CSV import wizard at `/import` (`expo-document-picker`, the web's `/api/polish-imports` flow and review rules ported to `src/lib/polish-import.ts`, inventory caches dropped after commit). The polish detail also shows **wear history** (`WearHistory`: the newest manis the polish was worn in, "See all" → the Manis tab with `?shade=`, #427); the Collection Wishlist preset and the Insights Wishlist panel show the per-currency **wishlist value** of brand list prices (`sumListPrices` in `packages/shared`, `lib/use-wishlist-value.ts`, #437); and the Looks screen takes the shared **skin tone** input (undertone + depth, persisted per user, #434).
