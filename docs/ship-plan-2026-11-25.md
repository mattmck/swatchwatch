# Ship plan: get SwatchWatch into Angela's hands, then out the door (2026-11-25)

This replaces "two goals" as the list of what is being worked on. The two goals (Rapid Add on real
bottles, a full catalog) stay; what changes is that each piece of work now has to serve a ship date.
Detail and history for the two goals remain in `docs/plan-2026-11-10-rapid-add-and-catalog.md`.

## Where things stand (checked 2026-11-25)

| Question | Answer |
|---|---|
| Is prod current? | No. Prod was last deployed 2026-10-27; `dev` is 25+ commits ahead (all of the brand-sources ingestion, the bottle matcher work, the admin Sources tab, 18 migrations). Prod has the guided bottle flow switched on, running that older code. |
| Does sign-up / login work? | The code path is sound on web and mobile. Three things can still stop a new person: tenant settings nobody has checked in prod (#530), a race on the very first page load that shows "Authentication failed" (#525), and a cancelled sign-up that shows nothing (#525). No automated test signs in against a deployed site. |
| Do we need to automate Rapid Add testing? | A little. The matching rules have about 700 unit tests and a photo eval (49 / 52 matched at 480 / 1920 px, 0 wrong matches with #524). What has no test is the join: camera → page → API → inventory row. Nothing that needs a live API runs in CI (#526), and the page and camera component have no browser test (#534). |
| Are we missing a lot of polishes? | Yes, and mostly for one reason: ingestion only runs when an admin starts it (#532). Locally the catalog has 7,349 active shades from 48 brands; deployed dev and prod have none of the November sources (#529). 28 enabled brand stores have never run anywhere, about 30 sources wait on permission, and about 29 known brands have no source (#535). The `barcode` table is empty, so barcode scans cannot match yet. |
| Is a missing bottle a dead end? | No. Manual add, Rapid Add "Add manually" / label photo and the create card all make a private shade. It is not linked to the catalog when the catalog later gains that shade (#536). |

barcode or bottle scan answers correctly for her brands, and a bottle we do not know costs a few taps.

### Parked (milestone "Parked")

Not worked on until Ship 3 is done: hex-detection model tuning and the ground-truth gate (#322),
multi-colour shades, the pile, bins and display boxes, launch radar, the ESM migration (#2), the
feature-flag service decision (#313), photo matching extras (#105), #326, #274, #109.

Hex detection itself is not parked: measured colours are part of #529. What is parked is choosing a
better model, because colour is now only a tie-breaker (#524) and no longer blocks a match.

## Rules for the next three weeks

1. A piece of work needs an issue in Ship 1, 2 or 3. Anything else goes to Parked.
2. Rapid Add changes are judged by the photo eval (matched count, 0 wrong matches) and, from Ship 2,
   by Angela's real scans (#537).
3. "Not in the catalog" is an ingestion to-do (#535), not a matcher bug.
4. One release per milestone; `dev` is deployed to prod at the end of each.
