# Web App — `apps/web`

Next.js 16 (App Router) + Tailwind v4 + shadcn/ui.

## Running

```bash
# From repo root
npm run dev:web          # → http://localhost:3000
npm run build:web        # Production build
npm run test --workspace=apps/web   # Web unit tests
```

## Auth System

**Dev Bypass Mode** (`NEXT_PUBLIC_AUTH_DEV_BYPASS=true`):
- Skips MSAL initialization entirely
- `getAuthHeaders()` returns `Bearer dev:1` (or `Bearer dev:2` for admin calls)
- All MSAL-dependent components render fallback/stub states

**B2C Mode** (when `NEXT_PUBLIC_B2C_TENANT` and `NEXT_PUBLIC_B2C_CLIENT_ID` are set):
- MSAL initializes via `PublicClientApplication` in `auth-provider.tsx`
- Login requests include OIDC scopes plus an API scope (`api://<client-id>/access_as_user` by default)
- User signs in → `auth-provider.tsx` registers a token provider in module-level `auth-token.ts`
- `getAuthHeaders()` calls `getFreshAccessToken()` on every API call: MSAL `acquireTokenSilent` returns the cached token or renews it once it is within 5 minutes of expiry (`tokenRenewalOffsetSeconds`), so a long-open tab never sends an expired token. Concurrent calls share one acquisition (`createAccessTokenProvider` in `src/lib/token-renewal.ts`)
- **Any** silent failure (interaction required, expired refresh token, hidden-iframe errors such as `block_iframe_reload` or `timed_out`) redirects to interactive sign-in (except a network failure, see "Offline" below), at most once per 30 s (`claimTokenRedirect`, sessionStorage guard); the app never keeps running on a missing token. `<RequireAuth>` also shows the sign-in prompt for an account without an API token
- Silent renewal that needs the hidden iframe loads `/blank.html` (`SILENT_REDIRECT_PATH` in `msal-config.ts`), not the app root. The page only runs MSAL's redirect bridge (`broadcastResponseToMainFrame`), which msal-browser v5 requires to hand the response back over `BroadcastChannel`. Its script, `public/msal-redirect-bridge.min.js`, is copied from the installed `@azure/msal-browser` by `scripts/copy-msal-redirect-bridge.mjs` before `dev`/`build` (gitignored). **`<origin>/blank.html` must be registered as an SPA redirect URI on the Entra app registration** for every web origin (prod: `https://swatchwatch.app/blank.html`, `https://www.swatchwatch.app/blank.html`; dev origin; `http://localhost:3000/blank.html`); until it is, iframe renewal times out and the user is sent to sign-in
- `<RequireAuth>` guard on `(app)` routes triggers login redirect if unauthenticated
- `<UserCard>` displays user info and sign-out button in sidebar

**Deterministic sign-out:** `useAuth().logout()` calls `logoutRedirect()` with explicit parameters so behavior is consistent in multi-account browser sessions:
- `account` — the active account (`getActiveAccount()`, falling back to the first cached account), so MSAL signs out the specific SwatchWatch session instead of prompting "which account to sign out of"
- `postLogoutRedirectUri` — `window.location.origin + "/"`, returning the user to the app root
- `logoutHint` — sourced from the account's `login_hint` optional claim when present (recommended), falling back to `account.username`, which can let the IdP skip the account picker entirely

This works for both `ciamlogin.com` (External ID) and `b2clogin.com` (legacy B2C) authorities. For the most reliable promptless logout, configure the `login_hint` optional claim on the Entra app registration so it is emitted in the ID token.

**Hooks:**
- `useAuth()` — B2C mode only, calls MSAL hooks (`useMsal`, `useIsAuthenticated`). Returns `{ isAuthenticated, user, role, isAdmin, login, logout }`. Must be inside `<MsalProvider>`
- `useDevAuth()` — Dev bypass stub, safe to call anywhere. Returns stubbed auth state with admin role for local testing
- `useUnconfiguredAuth()` — B2C-unconfigured stub, safe to call anywhere. Returns unauthenticated non-admin state

## Admin Hex Labeling tab

`/admin?tab=hex-labeling` (`reference-data/components/hex-labeling-tab.tsx`; the per-shade sampler UI lives in the shared `components/shade-hex-labeler.tsx` + `hex-sampler.tsx`, which `/polishes/detail` also uses for admins via `AdminHexSipPanel`, #351) builds ground-truth hexes for the hex-detection eval. It walks the admin queue from `GET /api/hex-labels-admin/queue` (unlabeled shades with images first, worst vendor↔detected agreement first; filters: brand, "Vendor ≠ detected" (`hex_agreement > 0.10`), "Show labeled", "Include no-image shades"; cursor-paginated, the next page is prefetched near the end) and shows, per shade, brand/name/finishes, the vendor/detected/name hexes as swatches with the OKLAB agreement, and every catalog product image (thumbnail strip, keys 1–9).

- **Eyedropper:** the selected image is drawn into a `<canvas>` (loaded with `crossOrigin="anonymous"`; the image proxy returns `Access-Control-Allow-Origin` for allowed web origins). Hovering shows a 10× magnifier loupe with the sample window and a live "Under cursor" swatch; clicking or tapping (pointer events, `touch-action: none`) picks the averaged colour of a 1×1/3×3/5×5/9×9/15×15/25×25/41×41/61×61 window (default 5×5, `[`/`]` to change), ignoring fully transparent pixels. The large windows average across glitter, flakies and shimmer; the sample window is also outlined on the image, and the loupe zooms out so the whole window stays visible. Chromium browsers also get a native `EyeDropper` button (E). If an image cannot be read (no CORS headers → tainted canvas) the tab still shows it and explains that only the native eyedropper or a typed hex will work.
- **Save:** the picked hex can be adjusted in the hex input; optional "Images unreliable" flag and a note. Enter saves (`POST /api/hex-labels-admin/labels`, with the image id and normalized sample point) and advances; S skips, N/→ and P/← navigate, U (or Ctrl/⌘+Z) undoes the last save (deletes a new label or restores the one it replaced). A warning shows when the sampled image has no public vendor URL (such labels are not exported to the eval fixture). The progress bar shows labeled / total for the current filters.
- **Type and finishes:** pills above the swatches mark the shade a topper, top/base coat, treatment or accessory (saved on click; sticky; a non-color shade leaves the queue at once and the next shade shows, `applyQueueItemChange` in `lib/shade-classification.ts`) and set its finishes from the finish catalog, primary first (saved with the label or with "Save finishes"; sticky, so ingestion never re-adds a removed finish).
- Labels never change the shade's `vendor_hex` / `detected_hex` on their own. **Promote to vendor hex** (#321, D12) is a separate, confirmed per-label action on a saved, non-unreliable label: it copies the label's hex to `vendor_hex` (marked `manual_label`, which ingestion never overwrites; audit-logged) and shows "Promoted" with an Undo that restores the previous vendor hex.

## Admin Bottle Eval tab

## Offline: saved copy of the collection

The PWA is the in-store path, so "My Collection" opens from the last loaded copy when the API is unreachable (stale-while-revalidate, the web twin of the mobile `api-cache.ts`).

- **What is saved** (`src/lib/api-cache.ts`, localStorage, key `swatchwatch:api-cache:v1:<account>:<name>`): the first page of the `/polishes` My Collection preset (`status=owned` alone; the search / finish / family / category / sort / page-size set is part of the key; the tone filter and other pages are not saved) and every owned polish whose detail page was visited. Entries are versioned, expire after 7 days, and are tied to the signed-in account (`setApiCacheUser(homeAccountId)` from `auth-provider.tsx`; dev bypass uses a fixed id). A different account signing in wipes the previous account's copies; sign-out (`useAuth().logout()`, MSAL `LOGOUT_SUCCESS`) calls `clearApiCache()`.
- **Size guard:** an entry is capped at 300k characters (list rows are dropped from the end, the true `total` is kept), the whole cache at 1.5M characters (oldest entries evicted first), at most 6 list sets and 40 details. Storage errors (private window, quota) just mean no saved copy.
- **Private media is never saved.** Owner-scoped `v3` image URLs are stripped before writing (`stripPrivateMedia`) and the bytes of private images are never stored; the nail photo panel shows a placeholder offline. Public `v2` catalog thumbnail URLs are kept as strings (they expire; the hex swatch is the fallback).
- **Behaviour:** the page shows the saved first page immediately while the request runs. If the request fails because the API cannot be reached (network error, 502/503/504, or the browser is offline; `isApiUnreachable` in `src/lib/offline.ts`) the saved copy stays under a "Showing your saved collection from <time>; some actions are unavailable" banner (`SavedCopyBanner`) with a Retry button; it refetches on the browser's `online` event (`useOnlineRetry`). Writes (quick actions, stepper, Log mani, Rebuy, Edit, Delete, Recalc, Import, Add Polish, Pick for me) and Export are disabled meanwhile. Real answers (401, 404, 500 ...) are never masked by a saved copy.
- **Offline-safe auth:** a silent token renewal that fails because of the network (`isOfflineRenewalFailure`: `navigator.onLine === false`, a fetch `TypeError`, or MSAL `no_network_connectivity` / `network_error` / `endpoints_resolution_error`) no longer redirects to sign-in. `RequireAuth` lets a cached account through (`isAuthOffline()`), and renewal resumes on the `online` event or the next API call. Online failures (interaction required, expired refresh token, iframe errors) still redirect.
- **Telemetry:** `collection.offline_shown` (`surface` = `list` / `detail`, `age` bucket) once per saved copy shown.
- **Cold offline launch (service worker):** `npm run build` (in `apps/web`) runs `scripts/build-sw.mjs` after `next build`, which writes `out/sw.js` from `scripts/sw-template.js` (not run in `next dev`). The precache list (`scripts/sw-precache.mjs`) is `/`, `/dashboard/`, `/polishes/`, `/polishes/detail/`, `/rapid-add/`, `/manis/`, the `/_next/static` scripts, styles and fonts each of those pages references, `/blank.html` (the MSAL redirect bridge) with `/msal-redirect-bridge.min.js`, the manifest and the icons; source maps, `/api/*` and files over 1.5 MB are left out. The cache name carries a hash of the list and file contents, so every deploy gets a new cache. Request rules live in `scripts/sw-core.mjs` (shared with the unit tests): `/api/*` (so `/api/images/*` and private `v3` URLs too), cross-origin, non-GET, `Authorization`-bearing and Range requests pass straight through and are never cached; precached assets are cache-first; unseen hashed `/_next/static/*` chunks are cached on first use; page navigations stay network-first (5 s timeout) with the precached page (else the `/polishes/` shell) as the offline fallback. Registration (`src/lib/service-worker.ts`, from `TelemetryProvider` after hydration) happens in production builds only; `next dev` unregisters any worker. A new worker installs but waits; the page shows an "Update available" toast whose Reload button posts `SKIP_WAITING`, and the page reloads once the new worker takes over. `public/staticwebapp.config.json` serves `/sw.js` with `cache-control: no-cache` so a deploy's new worker is picked up on the next load. Telemetry: `pwa.sw_installed`, `pwa.sw_updated`.
- **Not included yet:** no offline writes; catalog search is not saved; pages outside the precache list (admin, look/wishlist share pages) need the network.

## Environment Variables

All web settings are build-time `NEXT_PUBLIC_*` variables, inlined into the static export: set them in `apps/web/.env.local` for `next dev` / `next build` (Next.js reads env files from `apps/web`, not the repo root; restart after changing), and in `.github/workflows/deploy.yml` (GitHub environment variables/secrets) for deploys, not in Static Web App app settings. They are public, so never put secrets in them.

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_API_URL` | API base URL used by `src/lib/api.ts` (default `http://localhost:7071/api`). Also the only host that receives telemetry correlation headers |
| `NEXT_PUBLIC_SITE_URL` | Absolute site origin for `metadataBase` in `src/app/layout.tsx` (Open Graph / canonical URLs); default `https://swatchwatch.app` |
| `NEXT_PUBLIC_APPLICATIONINSIGHTS_CONNECTION_STRING` | Enables browser telemetry (`src/lib/telemetry.ts`). Unset = no-op (local dev default). Set at build time by `deploy.yml` from the Terraform output `application_insights_connection_string` |
| `NEXT_PUBLIC_APPINSIGHTS_SAMPLING` | Browser telemetry sampling percentage, `(0, 100]`; default `100` |
| `NEXT_PUBLIC_AUTH_DEV_BYPASS` | Dev-only bypass toggle. When `true`, the UI sends `Authorization: Bearer dev:1` on authenticated API calls. Set to `false` for production or to test B2C auth locally |
| `NEXT_PUBLIC_AUTH_DEV_ADMIN_USER_ID` | Optional dev bypass user id used for admin-only API calls (the `/admin` console; defaults to `2`). Ignored when `NEXT_PUBLIC_AUTH_DEV_BYPASS=false` |
| `NEXT_PUBLIC_B2C_TENANT` | Entra tenant short name (e.g., `myorgdev`). Empty or missing → auth skipped, unconfigured fallback mode. When set with `NEXT_PUBLIC_B2C_CLIENT_ID` → MSAL initialized |
| `NEXT_PUBLIC_B2C_TENANT_ID` | Entra External ID (CIAM) tenant GUID. Required for CIAM tenants: the MSAL authority becomes `https://<tenant>.ciamlogin.com/<tenant-id>` so the metadata issuer (`https://<tenant-id>.ciamlogin.com/<tenant-id>/v2.0`) passes msal-browser 5.x issuer validation. When omitted for a CIAM policy, MSAL is not initialized and the app uses unconfigured-auth mode. Unused for legacy `B2C_1*` policies |
| `NEXT_PUBLIC_B2C_CLIENT_ID` | Entra app registration client ID. Must be set alongside `NEXT_PUBLIC_B2C_TENANT` to enable auth |
| `NEXT_PUBLIC_B2C_API_SCOPE` | Optional API scope(s) for access tokens (space-delimited). Defaults to `api://<NEXT_PUBLIC_B2C_CLIENT_ID>/access_as_user` when unset |
| `NEXT_PUBLIC_B2C_SIGNUP_SIGNIN_POLICY` | Policy/user-flow selector. If it starts with `B2C_1`, the app uses legacy `b2clogin.com` policy authority. Otherwise it uses `ciamlogin.com` authority and sends `p=<value>` query parameter on auth/token requests (for External ID tenants). |

**Note:** When both `NEXT_PUBLIC_B2C_TENANT` and `NEXT_PUBLIC_B2C_CLIENT_ID` are empty, the app runs in **unconfigured mode**: marketing pages work, but `(app)` routes show a "Sign in" prompt that warns the user B2C is not configured.

## Telemetry & Error Boundaries

Browser telemetry goes to the same Application Insights resource as the Functions API (plan: `docs/observability-plan.md`).

- **Off by default.** `src/lib/telemetry.ts` does nothing unless `NEXT_PUBLIC_APPLICATIONINSIGHTS_CONNECTION_STRING` is set at build time. To try it locally, put the dev connection string in `apps/web/.env.local` and restart `next dev`.
- **What's collected:** page views (initial + App Router `pushState` navigations), unhandled errors and promise rejections, `fetch` dependencies, and anything sent through `trackEvent` / `trackException`. Requests to the `NEXT_PUBLIC_API_URL` host carry a W3C `traceparent`, so a browser fetch and the Functions request it hits share one `operation_Id` in **Transaction search**. No other origin gets correlation headers (B2C and blob storage would reject them on preflight).
- **Privacy:** telemetry carries the internal user id only (never the email), and capabilities are redacted: `/api/images/{id}` ids plus shared-wishlist and shared-look tokens (`/api/wishlist/{token}`, `/api/look/{token}`, and the `/w/?token=` and `/l/?token=` page URLs). The SDK sets its default `ai_user` / `ai_session` cookies; whether to keep them (or set `disableCookiesUsage: true` in `buildTelemetryConfig`) is an open decision.
- **Collection events (#262):** `collection.status_changed` (`from`, `to` — `none` for a catalog-only row — and `via`: `quick-action`, `menu` or `stepper`) and `collection.tried_changed` (`tried`, `via`) after a successful row update on `/polishes`; `collection.summary` (`owned`, `untried`, `untriedPercent`, `wishlist`) on each dashboard load, for the Sprint 1 status-adoption metrics.
- **M2 metric events (D19, #323):** built in `src/lib/metrics-events.ts` (counts and enum values only, unit-tested). `dupe.warning_shown` when the add guard dialog opens (`surface` = `add_form` / `wishlist` / `rapid_add`, `dupeCount`, `bestGrade` = `HIGH` / `MEDIUM`, plus `page`, `intent`, `shade`, `verdict`, `highCount`, best dupe finish compatibility/distance); `dupe.warning_outcome` when it is answered (same plus `outcome` = `cancel` / `wishlist_instead` / `add_anyway`, `via` = `button` / `dismiss` / `dupe_link`, `suppressed`); `mani.logged` for a new mani (`polishCount`, `via` = `quick` / `form`); `match.image_processed` / `match.result_action` on `/polishes/match` (#105, see `docs/observability-plan.md`); `import.completed` on a CSV import commit (`rowsCommitted`, `created`, `updated`, `skipped`, `failed`, `shadesCreated`). The Rapid Add verdict card emits them with `surface = rapid_add`. Funnel KQL and the weekly DB query: `docs/observability-plan.md` ("M2 success metrics"). Roadmap metric: share of `dupe.warning_shown` ending in `cancel` or `wishlist_instead` (target > 20%).
- **Add guard events (#266):** `add_guard.check_failed` (`reason` = `error` / `timeout`; the add went ahead unchecked). The dialog's shown/answered events are the `dupe.*` events above (they replaced `add_guard.shown` / `add_guard.choice`).
- **Error boundaries:** `(app)/error.tsx` and `(admin)/error.tsx` report via `trackException` and show `ErrorState` with a retry (`reset()` re-renders the segment; the pages fetch client-side, so that refetches too). `app/global-error.tsx` catches root-layout failures. They're all client components, so they work with `output: "export"`.

## Conventions

- **Path alias:** `@/*` maps to `src/*` (configured in `tsconfig.json`)
- **Types:** Import domain types from `swatchwatch-shared`, not local redefinitions
- **Styling:** Tailwind v4 utility classes. CSS variables for theming in `globals.css`. Inline `style` only for dynamic color values (e.g. `backgroundColor: polish.colorHex`)
- **Client components:** Pages with interactivity use `"use client"` directive. Server components used where possible (e.g. `polishes/[id]/page.tsx`)
- **Data:** All pages now use the live API. The old `mock-data.ts` is no longer used.
- **Back navigation (#348):** keep list/filter/selection state in the URL (`router.replace`, see `polish-list-url.ts`, `color-search-url.ts`, `gaps-utils.ts`) and build every link to `/polishes/detail` with `detailHref()` so the detail page's back link returns to the same state
